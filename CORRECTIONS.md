# Corrections policy

Report a possible error through a GitHub issue without including personal medical information.

Material factual, safety, retraction, or interpretation errors are handled immediately:

1. verify the report against the primary source or registry;
2. publish a patch edition such as `2026.08.1`;
3. describe the correction in the new edition changelog;
4. keep the original edition intact; and
5. attach a visible correction notice to every affected historical edition.

Typographical changes that do not alter meaning may be bundled into the next review, but they must still appear in version control.

The project will not erase an old claim merely because it became outdated. Historical snapshots remain available with a prominent superseded or correction notice and a link to the replacement edition.
